### POST /api/session/resolve
Resolves an open friction event.

**Request:**
```json
{
  "session_id": "uuid",
  "friction_id": "uuid",
  "resolution": "user_clarified",
  "input": "Key points only"
}
```

**Process:**
1. Update friction event state to `resolved` in `friction_events` table
2. Write `friction.resolved` to CP Log Store
3. If `user_confirmed` or `user_clarified` → retry message pipeline with resolution context
4. If `user_revised` → return to input — user rephrases
5. If `user_abandoned` → unblock input, no retry

**Response:**
```json
{
  "status": "resolved",
  "next": "retry" | "rephrase" | "unblocked"
}
```

### POST /api/session/satisfaction
User submits SS star rating. Completes IFI Phase 2 calculation.

**Request:**
```json
{
  "session_id": "uuid",
  "action_id": "uuid",
  "ss_rating": 4
}
```

**Process:**
1. Validate rating is 1–5
2. Normalize: SS = (ss_rating - 1) / 4 → 0.0–1.0
3. Load SA and CP from partial IFI record
4. Calculate composite: IFI = 0.4(SA) + 0.3(CP) + 0.3(SS)
5. Update ifi_scores record with SS and composite
6. Write `ifi.phase2` to Klear Events Store

**Response:**
```json
{
  "ifi": 0.84,
  "components": { "sa": 0.88, "cp": 1.0, "ss": 0.75 },
  "cp2_skipped": false
}
```

### POST /api/session/counterfactual
Returns alternative interpretations the IPP classifier detected but did not surface.

**Request:**
```json
{
  "session_id": "uuid",
  "action_id": "uuid"
}
```

**Process:**
1. Load IPP classification results for this action from `klear_events`
2. Filter to IPPs that were detected but not surfaced (below ICD threshold)
3. Call Claude to generate 2–3 concrete alternative interpretations based on detected IPP types
4. Return as selectable options

**Response:**
```json
{
  "original_interpretation": "Most cited papers in academic journals on AI alignment",
  "alternatives": [
    { "id": 1, "ipp_type": "authority", "interpretation": "Most cited by AI safety practitioners, not academics" },
    { "id": 2, "ipp_type": "scope", "interpretation": "Most cited including preprints and grey literature" }
  ]
}
```

**Selecting an alternative:**
User selects an alternative → frontend calls `POST /api/session/message` with the original message plus a resolution note: `"User selected alternative interpretation: [text]"` — this triggers a fresh pipeline run with the chosen interpretation injected into context.

## 6. Frontend Components

### 6.1 Session Start Screen
- Opening prompt input
- Articulation card — editable topic, goal, scope, exclusions
- ICD selector — three options with plain language labels
- Context Roots confirmation panel (registered users)
- Transitions to chat on confirmation

### 6.2 Chat Interface
- Message thread (scrollable)
- Input bar (disabled during open friction)
- Send button
- CP Status bar: context summary, intent, ICD level, domain indicator, session health

### 6.3 Friction Card Component
- Inline in message thread
- Amber/warning color with IPP type label
- Plain language explanation
- Specific clarification question for the detected IPP type
- Resolution buttons with explicit labels
- Input bar locked until resolved

**Friction types and their cards:**

| Type | Header | Question shown | Buttons |
|------|--------|---------------|---------|
| `ambiguous_signal` (IPP) | "Klear needs clarification" | The IPP clarification_question | Specific options + Rephrase + Abandon |
| `scope_boundary` | "Outside your scope" | "This seems outside what you declared. How would you like to proceed?" | Proceed anyway / Stay in scope / Update scope |
| `unverified_intent` | "Intent not set" | "Please confirm what you're trying to do before continuing." | Set intent |
| `missing_context` | "More detail needed" | "There's not enough context to answer accurately." | Add detail / Abandon |
| `conflict_detected` | "Conflict detected" | "This conflicts with something you declared earlier." | Keep original / Use new dir
