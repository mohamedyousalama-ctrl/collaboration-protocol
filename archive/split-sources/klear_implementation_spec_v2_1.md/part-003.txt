r confirms individual roots or removes them for this session
4. Confirmed roots injected into session context as pre-verified constraints

**Managing Context Roots:**
- `GET /api/context_root/:user_id` — list all active roots
- `DELETE /api/context_root/:root_id` — deactivate a root permanently
- `PATCH /api/context_root/:root_id` — edit root content

**Klear extension events (Klear Events Store):**
- `context_root.saved` when user saves a node as a root
- `context_root.loaded` with root IDs at session start
- `context_root.confirmed` per root confirmed by user
- `context_root.skipped` per root removed for this session

### 4.11 Klear Events Store — CP Log Compliance

**This section resolves the CP compliance issue with new event types.**

The frozen CP v1.0.1 specification defines exactly these log event types for the Log Store:
`context`, `intent`, `node`, `pivot`, `action`, `friction`, `guardian`, `signal`, `session`

The Log Store is append-only and must contain only these event types to maintain CP v1.0.1 compliance.

Klear introduces additional event types that are not in the frozen spec:
`icd.set`, `domain.classified`, `domain.shift`, `safety_floor.injected`, `decay.calculated`, `ifi.phase1`, `ifi.phase2`, `ipp.classified`, `ipp.filtered`, `context_root.saved`, `context_root.loaded`, `context_root.confirmed`, `context_root.skipped`

**Rule:** These events must NOT be written to the CP Log Store. They must be written to a separate `klear_events` table.

**Two stores, two purposes:**

| Store | Table | Contains | Append-only? | CP compliant? |
|-------|-------|---------|-------------|--------------|
| CP Log Store | `logs` | All frozen CP event types | Yes — enforced by RLS | Yes |
| Klear Events Store | `klear_events` | All Klear extension events | Yes — by convention | N/A — Klear extension |

**`klear_events` table schema:**
```sql
create table klear_events (
  id uuid primary key default gen_random_uuid(),
  session_id uuid references sessions(id),
  user_id uuid references users(id),
  action_id uuid,
  event_type text not null,
  event_subtype text,
  payload jsonb,
  created_at timestamptz default now()
  -- No updated_at — append-only by convention
);

create index idx_klear_events_session on klear_events(session_id);
create index idx_klear_events_type on klear_events(event_type);
```

The `logger.js` module must route every event to the correct store based on event type before writing.

### POST /api/session/message
Core endpoint. Runs full CP pipeline per message.

**Request:**
```json
{
  "session_id": "uuid",
  "message": "What are the most cited papers on AI alignment?"
}
```

**Process:**
1. Load session state (context, intent, nodes, roots, ICD, decay score, domain)
2. Run IPP Classifier → detect all IPP types with confidence scores
3. Apply ICD filter → determine which IPPs to surface
4. Run Intent Decay Calculator → compute δ, update D
5. Run Guardian Checkpoint 1 → decision based on filtered IPPs + scope + intent state
6. If decay D > 0.4 → trigger decay friction regardless of CP1 decision
7. If CP1 = Clarify/Refuse → create friction event, return friction card
8. If CP1 = Allow → run domain classifier on this message → check for domain shift
9. Call Claude API with system prompt + full context injection
10. Run Guardian Checkpoint 2 (if trigger conditions met)
11. If CP2 = Clarify/Refuse → create friction event, return friction card
12. If CP2 = Allow → run Safety Floor Injector if domain is high-risk
13. Calculate IFI Phase 1 (SA + CP)
14. Write action to Supabase, return response
15. Write all CP log events to `logs` table
16. Write all Klear extension events to `klear_events` table
