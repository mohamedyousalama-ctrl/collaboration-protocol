## 1. Product Overview

Klear is a multi-purpose AI assistant (Q&A, research, document analysis, code) powered by Claude and governed by the Collaboration Protocol (CP) v1.0.1. Every interaction is mediated by CP — intent is explicitly declared, the Guardian enforces boundaries, friction surfaces ambiguity before it becomes a wrong answer, and every decision is traceable.

**Core promise to users:** Klear only does what you actually declared. Nothing is inferred silently. Every answer is traceable to your verified intent.

**User tiers:**
- **Anonymous** — full CP session, no persistence across sessions
- **Registered** — Context Roots, session history, IFI trends, Compliance Report export, Klear Profiles

## 2. Architecture Overview

```
Browser (React)
    │
    │  user message
    ▼
Backend (Node.js + Express)
    │
    ├── [1] IPP Classifier (6-type taxonomy)        ← RUNS FIRST
    │       Scope / Temporal / Entity / Authority / Form / Abstraction
    │       Returns: [{ type, confidence, clarification_question }]
    │
    ├── [2] ICD Filter                              ← RUNS ON IPP RESULTS
    │       Read user's ICD setting (0.0–1.0)
    │       Surface only IPPs where confidence > (1 - ICD)
    │       Output: filtered IPP list to surface
    │
    ├── [3] CP Guardian Checkpoint 1 (programmatic)
    │       PC-1: filtered IPPs exist? → friction (ambiguous_signal)
    │       PC-2: signal out of declared scope? → friction (scope_boundary)
    │       PC-3: no verified intent in session? → friction (unverified_intent)
    │       PC-4: all clear → Allow
    │
    ├── [4] Intent Decay Calculator (parallel with Checkpoint 1)
    │       Semantic distance: current message vs declared intent
    │       Update session decay score D
    │       If D > 0.4 → trigger decay friction card
    │
    ├── [5] Domain Classifier (runs at session start + re-evaluated per message)
    │       Detect: health / legal / financial / general
    │       If domain shifts mid-session → activate new Safety Floor profile
    │
    ├── [6] Claude API call (if checkpoint 1 = Allow)
    │       System prompt: CP-aware permanent prompt
    │       Context injection: full session state
    │
    ├── [7] CP Guardian Checkpoint 2 (Claude-as-Guardian, conditional)
    │       Runs if: borderline IPP confidence (0.3–0.5) OR decay spike > 0.2
    │       Returns: allow / clarify / refuse + sa_score + cp_score
    │
    ├── [8] Safety Floor Injector (if domain = high-risk)
    │       Appends domain safety assertions to response
    │       Runs regardless of Guardian decision
    │
    ├── [9] IFI Phase 1 Calculator (immediate — after checkpoint 2)
    │       SA: from Guardian checkpoint 2 sa_score
    │       CP: active nodes satisfied / total active nodes
    │       Composite: pending SS — stored as partial IFI
    │
    └── Response → Browser (if Allow)
            OR Friction card → Browser (if Clarify)
            OR Blocked message → Browser (if Refuse)

    [IFI Phase 2 — async, after user submits SS rating]
    POST /api/session/satisfaction
        SS: normalized from user 1–5 star rating
        Final IFI = 0.4(SA) + 0.3(CP) + 0.3(SS)
        Stored in ifi_scores table
    │
    ▼
Supabase
    ├── CP Log Store (append-only) — guardian, friction, signal, action events only
    └── Klear Events Store — ifi, decay, domain, safety_floor, context_root events
```

## 4. CP Implementation

### 4.1 Session Start — Articulation Assistance + Intent & Context Declaration

Session start is a three-step flow designed to maximize intent clarity before the first AI call.

**Step 1 — Opening prompt shown to user:**
> "What are you working on today, and what kind of help do you need?"

**Step 2 — Articulation Assistance:**
After the user submits their opening statement, before confirming:
1. Backend calls Claude to extract structured context + intent + detected scope boundaries
2. User is shown an editable articulation card:
