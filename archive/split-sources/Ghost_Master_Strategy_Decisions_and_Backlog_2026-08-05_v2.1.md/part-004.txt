# 11. SCIENCE, EVIDENCE, AND CLAIMS

## 11.1 Evidence rule

Every material mechanism must be labeled as:

- established science or mature standard;
- strong but Context-dependent evidence;
- production-proven engineering;
- emerging technology;
- product hypothesis;
- unsupported or contradicted.

## 11.2 Current scientific research queue

The active ten-question research program covers:

1. Memory categories, expiry, and retention.
2. User approval granularity.
3. Encrypted local-memory synchronization.
4. Lost-device and account recovery.
5. Automatic explanation thresholds.
6. Ordinary versus forensic provenance.
7. Silent adaptation boundaries.
8. Local model and adapter updates.
9. Independent update verification.
10. The trusted boundary Ghost cannot modify.

## 11.3 Claims currently prohibited

Do not claim that:

- Ghost understands the true person;
- Ghost always knows the user's true intent;
- Silent Intent Inference is eliminated;
- CP provides universal safety;
- Ghost can control every app;
- local storage is automatically secure;
- the system is clinically validated;
- the current metrics are universally validated;
- the current corpus establishes population prevalence;
- the product will make every user outperform every peer;
- the product is production-ready;
- Kaggle or one benchmark alone proves real-world safety.

# 12. FALSIFICATION AND NARROWING

Use protected principles and falsifiable mechanisms.

Every major product hypothesis requires a Falsification Card containing:

- hypothesis;
- reason;
- baseline;
- test;
- evidence source;
- success condition;
- harm and guardrail conditions;
- continue condition;
- narrow condition;
- stop condition;
- time and budget limit;
- review authority;
- what remains unproven after success.

Examples:

## Ambient sensing

Continue only if it adds material value that selected digital sources cannot provide. Narrow if useful only in one Context. Defer or stop if low-data alternatives produce nearly the same benefit with less risk.

## LLM-history import

Continue if it recovers useful Context with low material correction and manageable third-party exposure. Narrow to selected projects if broad imports are unreliable. Stop if imports repeatedly convert AI-generated text into false user memory.

## Relational Presence

Continue if it improves comprehension, accepted outcomes, and control. Narrow to summonable task-bound use if dependence or capability confusion increases. Remove as default if harm exceeds value.

## Automatic actions

Continue if actions remain within permits, are reversible, save attention, and recover reliably. Narrow to Ghost-owned actions if external actions produce unacceptable false execution or false holds.

## First market

Continue only if target users repeatedly use and pay after experiencing the complete Ghost loop. Narrow to the segment showing strong recurring value. Change the wedge when interest does not become repeated use and payment.

## Live Work Field

Continue if concurrent episodes become easier to understand, target, and correct than in chat, list, or dashboard baselines. Narrow to high-concurrency Contexts if the pattern is valuable only there. Reject as a default if it increases overload, hides priority, or causes selection mistakes.

## Multi-target intent compilation

Continue if one intention produces separate correct plans with low review burden and zero cross-target Context leakage. Narrow to preparation-only if execution risk or correction burden is high. Stop external execution if aggregation creates authority errors, privacy leakage, duplicate effects, or false confidence.
